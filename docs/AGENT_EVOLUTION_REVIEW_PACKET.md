# Agent evolution — review packet foundation

`POST /api/admin/agents/evolution/preflight` accepts a JSON object with `baseCommit` (40 lowercase hexadecimal characters), `proposal` (10–2000 characters) and `patch` (at most 48,000 UTF-8 bytes). It returns a SHA-256 digest and byte count, `REVIEW_ONLY` and `executable: false`, with a checklist. It is protected by the existing Super Admin session/CSRF guard and process-local request limiter, limits the request stream, does not echo or persist the patch, and sets a private no-store response header. Submit only data you are authorised to handle; upstream infrastructure may have independent logging rules.

This is a **review metadata utility**, not an autonomous agent, patch parser, authorization decision, sandbox, approval workflow, file editor, evaluator, or deployment system. It does not verify that the commit exists, that the diff is valid, that paths are safe, or that any tests ran. The returned hash is not proof of origin or human approval. The operator must retain the patch and protect it separately. There is no UI or durable audit record for packets, no verified worker, and no connection to Brahma Evo. The existing rate limit is in-memory and is not a distributed production control.

Tests cover hashing, size and basic input validation, and source-level route assertions; real HTTP/session/CSRF tests, browser, distributed limiting, database and production tests have not run. Before enabling an actual code-editing worker: approve licences; establish an independent isolated worker, network/credential restrictions and resource limits; verify patch parsing, allowed paths and symlink handling, content-addressed artifact provenance, authenticated human approval, independent checks, durable audit and rollback. Protect the control plane and release policy from the candidate patch. Separate approval is needed for production deployment.
